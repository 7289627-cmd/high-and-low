# a06: store screenshot script

Script only, no game source changed. New files: `store/make_screens.py` and `store/fonts/` (Bagel Fat One 400 and Baloo 2 500/600/700/800 woff2, SIL OFL, copied from @fontsource; these are the only binary files in the patch).
Run: `python3 build.py && python3 store/make_screens.py` (flags: `--only iphone69,android`, `--no-marketing`, `--death anvil --death-ms 1500`, `--cut-ms`). The full run takes about 6 minutes.

## How it works
- Loads `artifact.html` (the offline build) inside a fake origin `https://hl.test/`, so localStorage works. All other requests are blocked.
- The real fonts are injected as data URIs. In every image Bagel Fat One and Baloo 2 render, with no fallback fonts.
- `HL_TEST_FILL_MS=250` makes the fill-in opponent join fast, so Play runs a real offline duel.
- Seeded state: name Maya, rating 1184 (Sharp), range 1-10,000. The opponent is renamed "Theo" through `G.players`. The secret is set to 7421 so the answer is always a clear YES and the range bar always shows the same cut.
- **Practice pill:** the in-game header shows "Practice" (mode 'solo') because the offline build has no network. It is hidden with one injected rule, `.bar .status{display:none}`. No game file is touched. The "Powers" button, mute and Leave are the real UI and are visible.
- Scenes:
  - Home: waits 2.6 s for the kite and landscape.
  - HIGHER/LOWER: reached by waiting for `[data-pickdir]`.
  - Ask slider: real mouse drag of `#sldTrack` to about 34%.
  - Range cut: the shot is taken 150 ms after `.rb.live` appears. It shows the red knock-out number -3,261.
  - Which one: `G.kn` is set to a 10-wide range with 4 numbers crossed out.
  - Death: the game's own `showScene('piano', me, 'Theo guessed 7,421!', ...)` captured at 1.6 s.
  - Win sheet: `G.phase='over'` then `showWinner()`. The game applies its own rating (+23, 1207) and shows "+5 coins" and "New hat unlocked: Crown!".
- Piano at 1.6 s beat anvil at 1.5 s. The piano frame shows Theo on top, the number on the piano and a flat bean with X eyes. The anvil frame is similar but less readable.
- The script writes every PNG as RGB, because both stores reject alpha.

## Sizes (verified)
| Folder | CSS size, scale | Pixels |
|---|---|---|
| iphone69 | 440x956, DSF 3 | 1320x2868 |
| iphone65 | 428x926, DSF 3 | 1284x2778 |
| ipad13 | 1032x1376, DSF 2 | 2064x2752 |
| android | 360x720, DSF 3 | 1080x2160 |
| feature | 1024x500, DSF 1 | 1024x500 |
| framed | | 1320x2868 |

- Apple (<https://developer.apple.com/help/app-store-connect/reference/screenshot-specifications>, read through a mirror link, with the sizes matched to device names by the page summary):
  - 6.9" accepts 1320x2868, 1290x2796 or 1260x2736.
  - 6.5" accepts 1284x2778 or 1242x2688. It is required only if there are no 6.9" screenshots.
  - iPad 13" accepts 2064x2752 or 2048x2732. It is required if the app runs on iPad.
  - Up to 10 screenshots per size. No alpha.
- Google Play (<https://support.google.com/googleplay/android-developer/answer/9866151>):
  - Screenshots are 320-3840 px, and the long side may be at most 2x the short side.
  - Up to 8 screenshots. PNG or JPEG without alpha.
  - Feature graphic is 1024x500 without alpha.
- The task suggested Android 1080x2400. That is 2.22:1, which breaks Google's "at most 2x" rule. I used 1080x2160 (exactly 2:1). 1080x1920 (9:16) also passes, but at 640 CSS px high the home landscape and the guess grid get cramped, so I did not use it.

## Not verified / issues found (not fixed, game source is out of scope)
- iPad: the game is a phone-width column centred on a 1032-wide screen, so the iPad shots look small and sparse. Apple requires iPad shots if the app runs on iPad. **Decision for the owner:** support iPad properly, or restrict the app to iPhone.
- Android 360 CSS wide: the "BWANG!" word in the piano scene is clipped on the left. At 360 wide the range-bar "N left" label can also be clipped. Both are in the game's CSS at narrow widths. A different death, such as `--death anvil`, avoids the first.
- Frames vary a little between runs because scene timing is real. The piano capture at 1.6 s can differ by a few tens of ms. Re-run with `--death-ms` to adjust.
- The win sheet shows "New hat unlocked: Crown!" because the profile's hat state is real game logic. It is acceptable for a store shot but is not controlled by the script.
- The sounds and the timer clock are the real UI. The timer value in each shot is whatever it was at capture.
- The Apple page itself could not be fetched directly. The mirror link was readable, and the 6.9" "optional" reading comes from that summary. Please confirm in App Store Connect.
