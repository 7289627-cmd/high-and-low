# a08: gapless music loop (src/music.js)
## Changed
- src/music.js rewritten (Web Audio). Reuses SFX.ctx (made by sound.js on the first gesture). Chain per track: track gain -> MUSIC.duckG -> MUSIC.out (mute gain) -> ctx.destination. It does not touch SFX.master, so SFX volume is unaffected.
- load(): fetch + decodeAudioData. MUSIC.src.<name> may be a string or an array, and the first candidate that decodes wins (ogg/m4a later, no code change).
- region(): scans all channels for samples above -60 dB and returns the audible start/end. Source is loop=true with loopStart/loopEnd set, started at loopStart. If the region is under 1 s it falls back to the whole buffer.
- sync(): one source per track (guarded by t.node), so no double copies. Equal-power (sin/cos) crossfade of 1.2 s. Mute (SFX.muted) sets out.gain to 0 and fades tracks out quickly. When the page is hidden it fades out in 0.3 s, then calls ctx.suspend() at 450 ms. It resumes on return and fades back in.
- duck(ms): duckG goes to 0.5 (-6 dB) in 0.15 s, then back to 1 over 0.6 s after ms.
- Public API kept: MUSIC.set, MUSIC.sync, MUSIC.vol, MUSIC.src, and the SFX.setMuted hook.
- Failed loads: a failure is remembered and retried at most 3 times, 20 s apart, so a network blip does not silence music forever.
- src/main.js showScene(): one line, try{MUSIC.duck(ms)}catch(e){}. showScene is also used for the 'bonk' scene (2.5 s), so that gets ducked too. Say if you want bonk excluded.
- Guards: MUSIC.init no-ops without SFX.ctx or fetch (jsdom ok).
## Verified (chromium, site/ over http.server, one click to unlock, temp 2.8 s and 4.3 s loops made from lab/music-jingles with ffmpeg, files removed afterwards)
- Both tracks decode. home: dur 2.760 s, loop 0.3157 to 2.3400 s. play: dur 4.332 s, loop 0.5147 to 3.7226 s. Padding and silence are excluded (I added 0.3 s and 0.5 s of leading silence and 0.4 s and 0.6 s of trailing silence).
- MUSIC.set switches tracks, and the old one stops after the fade. Rapid set calls leave exactly one node per track.
- duck(500): duckG.gain 0.5, then back to 1. Muted: MUSIC.out.gain 0 while SFX.master stays 0.8.
- Hidden: ctx 'suspended' and no nodes. Back: 'running', home node restarted.
- OfflineAudioContext seam render (+/-100 ms around the loop point, |x|<0.001 counted as quiet): trimmed loop max quiet run is 1.36 ms (home) and 0.84 ms (play). The untrimmed loop has a 200 ms quiet run at the seam. Both trimmed values are under the 5 ms limit.
- Missing files: no pageerror, no exceptions, and both tracks end up failed with no nodes. Chrome still logs "Failed to load resource 404" for the missing mp3s. That log comes from the browser, not from our code, and cannot be suppressed from JS. Other console errors in my runs were the sandbox proxy blocking Supabase and fonts.
- Checks: PASS quick play; PASS sfx files; mp_web ended with "errors [] []"; xss_check printed "host errors: []". (The first mp_web run crashed with a Node error. A rerun was clean. Cause unknown, probably timing.)
## Not verified
- Real iOS/Android WebView behaviour, e.g. ctx.suspend/resume under audioSession 'ambient'.
- Audible click at the loop point of real music. The loop point must be zero-crossing or musically seamless in the authored file. No crossfade-at-seam is applied.
- Real music files (none yet). Delivered patch contains no audio.
## Risks / decisions
- A 20-60 s track decodes to about 10-40 MB PCM per track in memory. Keep tracks short, or tell me if you want streaming.
- 404 console noise until the files exist (above).
- Patch is limited to src/music.js and src/main.js (the full-folder diff also lists path-only changes in build.py and tests).
