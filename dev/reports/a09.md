# a09 report: nickname filter

## What changed
- NEW `src/names.js`: global `nameOK(name, lite)` and `safeName(name, lite)` (returns the name, or 'Bean'). About 1.1 KB of rot13 word lists, whole file 3.4 KB. Added to `build.py` JS list before `rating.js` (so before main.js) for both builds.
- Matching: NFKD (strips accents, full-width), homoglyph map (Cyrillic/Greek look-alikes), leetspeak (0 3 4 5 7 @ $ ! | +), 1 read as both i and l, plus a third reading with digits dropped (so "Dick1" is caught), separators and emoji/zero-width removed, camelCase split ("BigDick"), stretched letters tolerated (each word becomes a regex, `fuuuck`, and a doubled letter in a word needs 2+ so "As"/"Bob"/"Con" pass while "Ass" does not). "scunthorpe" is cut out before matching.
- Two modes. Strict (public Play): SUBSTRING list + WHOLE-WORD list (whole name or any token) + impersonation (admin/moderator/official anywhere; mod, bot, staff, support, system, dev, owner, highandlow as whole words) + name must contain a letter (digits/punctuation/emoji-only blocked). Lite (friends rooms): SUBSTRING list only.
- `src/main.js`: removed `BAD`/`tameName`. `safeName` now applied in: `newLobby` (host's own name), `hostTick` (host's own name and every peer name copied into `G.players`, strict for `G.pub`, lite otherwise), `startOnline` and `startSolo` (name put in `myPres`, so the player sees 'Bean' in Play), `waitHTML` (own name on the search screen, strict), `cleanG` (every incoming player name, mode from `g.pub`).
- NEW `test/names.js` (296 cases) and a line in `run_tests.sh`.

## Why lite for friends
Friends rooms are private, joined by code. A strict list there only creates false positives (a friend called Dick, Cox, Mod). The strong slurs/sexual terms still never show. Impersonation and digit-only names are harmless in a private room.
