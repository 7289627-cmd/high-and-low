## Bugs found
1. FIXED `eloAtStake()` at rating 100 returned 1 (Math.max(1,min(me-100,..))) but a loss costs 0. Sheet said "You'll lose 1" and the exit cost nothing. Fix: `if(me<=100)return 0;`.
2. FIXED `eloApply` stored rating above 3000 (`to` not capped) while `myElo()` clamps to 3000, so the result sheet could show e.g. 3025 and the next game 3000. Fix: `Math.min(3000, ...)`.
3. NOT FIXED (cosmetic): a loss at the floor (rating 100) gives eloLast.d=0, sheet shows green "+0". Suggest showing "0" without sign/class when d==0, or hide the row.
4. NOT FIXED (decision): fill bot rating = max(700, mine±80). Players rated below ~780 face a bot up to 600 above them (rating 100 vs 700). Skill is floored at 0.1 so the bot is weak anyway, but wins pay big and losses almost nothing. Probably fine; owner to confirm.
5. NOT FIXED (decision): rating dodge: killing the app mid-duel costs nothing (no leaveGame runs); and when a human opponent leaves via Leave, the leaver loses but the stayer gets no win credit (guest path sets eloSkip, no eloApply(true)). Needs a product rule (e.g. record a pending game id at duel start and apply a loss on next launch).
6. Note: unknown G.max (friends default 1000) gets x1; only relevant if rated ever allows it. eloApply is also called every update tick after game over (cheap, guarded by the id).
