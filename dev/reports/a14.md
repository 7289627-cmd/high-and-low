# a14 security review (hostile player, modified client)

Patch: out/a14.patch (7 files: src/main.js, src/rating.js, src/net-supabase.js, build.py, test/xss_check.js, site/sounds.html, site/deaths.html). The patch omits the path-rewrite noise that the sandbox copy has in build.py and tests.

| # | Sev | Finding / exploit sketch | Status |

| 1 | high | Fake public host drains rating: joiner trusted every "over" state. A host cycling `gid` through play/over 8 times took a phone 1000 -> 684 (test reproduced). Fix: `eloApply` counts a result only if this phone saw that gid in `play` (`eloPlayGid`), `G.max` equals the mode it chose, and only once per room (`eloRoom`, reset in `leaveGame`). Now 1 loss max. | fixed |
| 2 | high | Friends-room host sets `pub:1` and the joiner's phone applied rating (880 after 3 fake games). Fix: `update()` forces `G.pub=0` unless this phone entered through Play (`isPub`). | fixed |
| 3 | med | Prototype pollution: a joiner with pid `__proto__` (or `constructor`) is accepted by the host; `G.st[a.pid]` on it makes `Object.prototype[0]++`. Also pids as keys in kn/st/bx/pk. Fix: `okPid()` (plain token, not in Object.prototype) in `rebuildPeers` and `cleanG`; kn/bt/st/bx/pk/xs/rs keys must be real player ids. | fixed |
| 4 | med | Oversize `G`: extra/nested fields on players, 5000-key kn/st/bx/pk objects, 100 KB strings in `sub`/`pr.need`. Every render does `JSON.stringify(G)`, so a hostile host can freeze phones. Fix in `cleanG`: drop object or >40-char extras on players, keys limited to player ids, strings sliced to 40. Test: 400 KB state shrinks to <20 KB. | fixed |
| 5 | med | Any peer in a room can send `role:host` presence; joiners take the LAST host-claiming peer. A third phone that learns a public room code (it is broadcast in the queue) can hijack the joiner, or pose as another player's pid (`act`/`rep`). No sender identity exists in Supabase broadcast. | needs decision (server or signed messages) |
| 6 | med | Host is authoritative: a modified host can declare itself winner, or ask unlimited questions and read the joiner's secret by binary search (`answerIfAsked`). A joiner can lose rating to a rigged host once per room (limited by #1). Rating stays local and editable. | accepted risk, needs server for real fix |

Adverts are validated (code `^[A-Z]{4}$`, n=1, max equals the picked mode, so no huge/invalid `max` can reach a phone); `opens` was unbounded, now capped at 64. | cap fixed; spam resistance needs decision (e.g. retry another candidate, ignore codes that failed) |

## Verified
- Before the fix the new tests FAILED on: bt keys, prototype pids, extras, key floods, __proto__ keys, strings, rating drain (1000 -> 684 after 8 games), friend-room pub switch (880).
- After: `cd test && node xss_check.js` -> `PASS security (no injected markup)`.
- `python3 build.py && python3 build.py web && node --check test/_built_web.js` OK. `node quick.js` -> `PASS quick play`. `node sfx_check.js` -> `PASS sfx files`.
- mp_web.js: game ran to the end (`END A: Jose wins! | B: You win!`), `errors [] []` (script has no PASS line; first run hit the 200 s cap under machine load).

## Not verified
- Real Supabase behaviour (payload size limits, rate limits); everything used the fake hub. Real browser CSP enforcement not run (jsdom ignores CSP).
- Native HLNative wrapper.

## New test cases (test/xss_check.js)
cleanG unit: poisoned max/timer/pub/el/bt, prototype pids, extras, key floods, `__proto__` keys, long strings. Public room: junk queue adverts (markup, huge n/max, wrong types, 4000 flood), joiner with markup name and bad `el`, fake host replaying 8 games, friends-room host forcing `pub`, host given a `__proto__` joiner.

## Decisions for owner
#5 and #6 (server authority or signed messages), #7 (matchmaking spam), #8 (clamp opponent rating), #12 (external script files), add `rated` to events.sql.
