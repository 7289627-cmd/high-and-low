## 5. Latent bugs (main.js unless noted; severity is my judgement)
1. net-supabase.js:123 `makeSupabaseQueue.getClient()` calls `createClient` per queue; `quickPlay` (main.js:731-767) builds a new queue on every Play tap and `leave()` only `removeChannel`s. Each tap makes a new Supabase client (own auth storage + realtime socket); expect "Multiple GoTrueClient instances" warnings and socket growth over a session (unverified, no network here). Fix: one shared client at module top, `createClient(url,key,{auth:{persistSession:false,autoRefreshToken:false}})` in lines 3 and 123.
2. main.js:263-270 `hbTimer` heartbeat interval is not cleared in `leaveGame` (:803). It self-clears on next beat (`heartOn()` returns 0 when `G` is null), so effect is at most one stray 'heart' check. Fix: add `clearInterval(hbTimer);hbTimer=null;hbPeriod=0;` to `leaveGame`.
3. base.js:13 `later()` pushes every timer id into `timers[]`, emptied only by `clearTimers()` (called from `leaveGame`); a long friends-room session grows it (a few bytes per turn). Low. Fix: also call `clearTimers()` in `toLobby` (main.js:713).
4. Event listeners: all `addEventListener` calls are top-level, once (main.js:828,829,1362,1380,1381,1399,1400; sound.js, music.js). None are inside `bind()`. No leak. `bind()` only reassigns `onclick`. OK.
5. Global `setInterval` main.js:1382 (1 s) never cleared, by design, guards `G&&G.players[G.turn]`. OK. `nbTimer/nbIv` (main.js:1355) not cleared on `leaveGame`, but self-stop when `.key.nb` is gone (300 ticks max). Low.
6. `G.players[G.turn]` unguarded sites: main.js:541, 547-548 (`beginTurn`), 1281 (`trayInner`, `cur.pid`), powers.js:51/57 (`pwPassTurn`). `cleanG` clamps `turn` to `players.length-1` and rejects empty player lists (main.js:173,186), and host only prunes players in the lobby (:363), so reachable only through a host-side bug; the one realistic path is `toLobby` (:713) filtering `hb` players and leaving `G.turn` out of range until `hostStart` resets it (:584, ok). No crash found. Fix if wanted: `const cur=G.players[G.turn]||G.players[0]` at :1281.
7. localStorage: every access goes through `LS` (try/catch, main.js:3-5), or try/catch in ads.js, sound.js, track.js. No uncaught write found in private mode. Side effect: in private mode `PID` (main.js:8) changes every load and `hl-coins`/`hl-elo` never persist (expected).
8. `fmt()` (base.js:9, `Number(n).toLocaleString`) on non-numbers: all call args come from `cleanG`-clamped ints (`ev.n`, `ev.x`, `rs[].x`, `q.x`, `q.n`) or local math. `fmt(r.v)` main.js:94 uses `st[3]` which can be `null` (cleanG keeps `null`); guarded by `a[i]==null` in `best()`. No NaN path found. `fmt(undefined)` would print "NaN".
9. `byPid(PID)` null: all dereferences are guarded (`me&&...`, `if(!me)return`) except powers.js:203 (`pwSheetHTML`: `pwCan(me,...)` with `me` possibly undefined if a spectator opens the sheet; the button is only rendered when `me&&me.a`, so low). Fix: `if(!me)return ''` at powers.js:203.
10. main.js:973 spectator text "A round is already going. You're watching..." and powers.js emoji in UI chrome (`⚡ Powers` :197,210, `👀` :214, power icons :5-9, `🛡️ ❄️` :189-190, bubbles :262-266) conflict with the owner's "no hints" and "no emoji in UI chrome" rules. TAUNTS (main.js:40) are emoji by design. Owner decision.
11. Perf, not a bug: `render()` (main.js:835) JSON.stringifies `G`, `ui`, presence each call to build `sig`; with `schedule` every 250 ms in public queue (`pubWake`) it re-stringifies the whole state 4x/s.
