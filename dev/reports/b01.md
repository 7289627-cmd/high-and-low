Run: `cd test && python3 real_browser.py` (~175 s, one Chrome at a time, server and browser killed at the end). Screenshots go to `test/shots/rb_<w>x<h>_<screen>.png` (390x844 and 320x568, 28 + 22 files; not in patch, shots dir is excluded).

## How it works
- http.server on a free 127.0.0.1 port serving `site/`. All non-local requests are aborted and counted. Fonts are fulfilled from local @fontsource files through the same https://fonts.gstatic.com URLs, so the CSP font-src is exercised and layout uses Bagel Fat One and Baloo 2. Without the files it WARNs and uses fallback fonts (`HL_FONT_DIR` overrides the path).
- Supabase: `vendor/supabase-*.js` is route-fulfilled with the same in-memory hub as test/quick.js. The real page runs `makeSupabaseRoom` and `makeSupabaseQueue`. Init script sets HL_TEST_Q/FILL/QJOIN_MS. Practice (`#soloBtn`) is `hidden` when HL_NEED_NET is set, so the test uses Play (rated duel with a fill bot) instead.
- Flow per viewport: home, "i" sheet, Play with friends (host lobby), Play (finding), wheel overlay if shown, secret slider (dragged), lock, pick direction, ask slider (dragged), Ask, death scenes through the real `showScene()` (all 11 at 390x844 and 320x568, 2 elsewhere), result sheet win and lose via `showWinner()`, game over screen. Death and result are forced by evaluate, not played out.
- Assertions per screen: scrollWidth<=innerWidth, body width, no control outside viewport horizontally, button text inside its button box (absolute badges ignored), no control below the fold with nothing that scrolls. WARN only: tap target <40px (aggregated), primary action below fold, ellipsis-truncated text.
- Global: console.error, pageerror and securitypolicyviolation events fail the run.

## Defects found (most severe first)
1. 320x568, ask slider: "Ask!" button (`#askGo`) bottom=580 > 568 viewport, nothing scrolls, so the main action is clipped by 12px (bottom edge of the button). Also tight for any phone with browser chrome (Safari toolbar leaves ~550 on a 667 phone; not tested). Fix: reduce the ask layout's vertical gaps or min-height on small heights (`@media (max-height:600px)` shrink bean/bubble block above the slider), or make the ask view scrollable.
2. 320x568, duel after asking: the bottom "Your turn" panel covers the lower half of the player's own card (hearts row cut) and the opponent name is ellipsised ("LilM..."). Screenshot rb_320x568_08_after_ask.png. Fix: at max-height:600px let the duel list scroll above the panel (padding-bottom = panel height) or shrink emoji panel.
3. 320x568, pick direction: the speech bubble "Is it..." and bean overlap the word "HIGHER"/"LOWER" text area at the boundary of the two big cards (rb_320x568_06_dir.png). At 390x844 the bean sits cleanly between cards. Fix: shrink bean/bubble or push the labels away from the seam at max-height:600px.
4. 320x568: lock-in (`#lockBtn` bottom=631), Play again on result sheet (`#againBtn` bottom=617) and Start in lobbies are below the fold but reachable by scrolling. Secret-picking has the primary button off-screen at 568 high (WARN). Fix: tighter bean height at short viewports.
5. Friends lobby 360x640 and 375x667: own name "Dodgy" (5 letters) is ellipsised to 33-48px because YOU and HOST tags plus "Change look" take the row (`.prow2 .who b`). A 12-letter name will be worse. Fix: let tags wrap under the name or drop "Change look" to an icon at <=375.
6. Join-code input at 320 wide: placeholder "CODE" is clipped to "COD" (rb_320x568_03_friends.png, `#codeIn` in `.join-row`). Fix: smaller letter-spacing or font-size for the placeholder at <=330px, or flex ratio change.
7. Missing `music/home.mp3` and `music/play.mp3` return 404 from `site/` (src/music.js:5). The code tolerates it, but it is a console error in the shipped build and the app wrap. Test downgrades it to WARN. Ship the files or drop the loader.
8. Tap targets under 40px (WARN, all viewports): Leave 72x36, Powers 106x36, Back 66x36, Change look 116x36, Add a bot 111x36, range chips 32px high (1-100, 1-1,000, 1-10,000, 1-100,000, Off, 20 sec, 40 sec), HIGHER flip button 33-39px high below 430 wide, info-sheet links Privacy 46x22 and Terms 38x22, and the "show" button 31x18 (appears in 32 screens). ## Not verified / limits
- Death scenes and result sheets are forced, not reached by playing to the end (a played-through game needs ~1 min per viewport). Wheel is dismissed by closeOv(), only audited while up (it did not show in the last run's timing for a few viewports, guess: depends on who starts).
- No multi-touch, real keyboard, safe-area insets (env()) or real Safari behaviour. Chrome is not WebKit, so iOS-specific layout bugs stay unchecked.
- Screens were checked by eye only at 390x844 and 320x568 (screenshots listed above); 390x844 looked clean (home, info, lobby, secret, direction, ask, result).
