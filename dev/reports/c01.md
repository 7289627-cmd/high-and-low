# c01 report: rated duel fairness (quit-dodge, leaver credit, floor, clamps)

Patch: out/c01.patch (src/main.js, src/rating.js, src/zz_c01.css new, test/duel.js). The patch holds only these 4 files; the sandbox path rewrites in build.py/tests/etc. are left out. No binary files.

## Changes
1. Quit-dodge (rating.js eloPend, eloPendBoot, pendClear; main.js update(), leaveGame(), boot IIFE). Key `hl-pend` = {gid, stake, at}. Written by update() each tick while a rated duel is in 'play' (only if stake>0, mode matches, once per game id). Cleared when the game reaches 'over', when knocked out, and in leaveGame() always (so Leave sheet, host-lost, host-left, Play again, X all clear it). On launch (after initRooms) eloPendBoot() applies the stored stake as a loss (counter +1, hl-elo-g = gid, so once-per-id), removes the record, and flashes "−N" (red, display font) after the rating in the home pill for 4 s (eloShow, .elo-fl in zz_c01.css). No sheet, no sentence. Junk records: gid must be a string, stake capped 0..80.
   - Rejoin rule: Play rooms are never saved in hl-session (startOnline saves it only for friends rooms), so a Play duel can never be rejoined; the loss always applies. Friends rooms/practice never write a record (G.pub is 0).
   - Host vanished: both paths in update() (explicit leave `gone`, 60 s lost) call leaveGame() with eloSkip, which clears the record. Verified in test.
2. Opponent leaves (a13 bug 5). Opponent leaving = presence `gone` (the 'bye' broadcast sent by leaveGame). Host stayer: hostTick, in the `pp.pres.gone` branch, if rated (G.pub, phase 'play', 2 players) sets phase 'over', win = me instead of the bot takeover; the normal over path then rates the win with the mode multiplier and shows the normal win sheet. Joiner stayer (host left on purpose): update() credits eloApply(true) + stGame before leaving, and shows "+N" in the home pill (no result sheet, because G is replaced by the host state every tick and the room is gone). Leaver pays the normal loss through the Leave sheet. Tested both directions: stayer 1000->1020, leaver 1000->980, applied once, pending cleared, stayer leaving later costs nothing.
   - Abuse: leaver cannot gain; stayer credit needs this phone to have seen the game in play at the chosen mode and once per room/gid (existing eloApply guards). A hostile host can only gift the joiner a win once per room. Secrets phase: no credit (leaving then is free), bot takeover as before.
3. Floor "+0": eloResultHTML shows plain "0" with no up/down class when d is 0 (eloDeltaTxt; also used for the flash).
4. eloOpp() clamps opponent rating to mine +-300 in eloApply and eloAtStake (sheet stake still equals the real loss).
5. addFillBot: el = clamp(mine+-80, 100, 3000) (was max(700, ...)). eloSkill(el) is 0.1 (weakest) at 720 and below, so low-rated players get the weakest bot. Test checks within 80 for 100,130,250,500...; skill 0.1 for <=300.

## Owner to confirm (rules I chose)
- A killed/closed Play duel costs the same loss as the Leave sheet, applied at next launch, whatever the time passed (no expiry).
- Stayer wins only when the opponent leaves on purpose (explicit Leave). If the opponent just disappears (app killed, signal lost), the host phone still swaps in a bot as before and no win is credited; the vanished player pays on next launch. Joiner whose host left on purpose also gets the win (shown as +N on the home pill, no sheet). Host vanishing without Leave: no win, no loss for the joiner.
- Leaving in the secrets phase stays free and gives no credit.
- Opponent rating clamp +-300; fill-in bot at floor rated 100-180.
## Risks / notes
- Two tabs/windows of the same browser share localStorage: opening a second tab while a duel runs in the first would apply the pending loss early (the first tab's result is then ignored by the id guard). Not mitigated.
- A tab that is reloaded or evicted by the phone mid-duel counts as a quit.
- Bug outside scope: 90 s lost-peer takeOver still has no credit (see above).
