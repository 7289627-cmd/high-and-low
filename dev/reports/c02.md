## Changes
1. Dead adverts (quickPlay): `QFAIL` map remembers a code whose join failed for 120 s on this phone; `pick()` skips them. Flow is now: listen 2 s, try best live advert, if it fails try the next best (max 2 tries), then host. The queue channel stays open during tries (so it is reused for our own advert and for fresh adverts); `reset()` leaves the failed room without closing it. Join timeout default HL_TEST_QJOIN_MS 6000 -> 3000. When we host after failed tries, `pubAt` is back-dated by the time spent (cap 5 s) so the fill bot is not delayed again. Advert validation unchanged.
   Measured, real defaults, two dead adverts then host (jsdom + fake hub): game started after 10.96 s (old code: 2+6+5+1.5 = 14.5 s for one dead advert). No advert: unchanged (about 8.5 s). One dead advert: about 7.9 s.
2. Race: EXISTS in base2. Proof (base2 build, 120 ms fake latency, A and B press Play 0 ms apart): both hosted, each "secrets n:2 humans:1" (each got a bot). Fix in quickPlay `host()` -> `my.merge`: while hosting alone in the lobby (1 player, no player peer) and a fresh advert with n=1 and a smaller code is heard, abandon the room and join it. One merge per search (`my.merged`), failed codes are skipped, a failed merge falls back to hosting. Test 2 (3 trials, gaps 0/40/80 ms): both in same room with 2 humans, one host, rooms stable 1.2 s later (no loop). Existing quick.js case (B 600 ms later) still passes.
3. Client reuse (net-supabase.js): `hlSharedClient(cfg)` one client for queue and rooms. Test (4 Play taps + Leave): Supabase clients created 5 before (base2, 1 per tap + 1 room) -> 1 after. Channels open after leaving: 0 before and after (the old code already removed the channel; the pile-up was clients/sockets), peak while searching 2.
4. hbTimer: verified not cleared in leaveGame (it only self-cleared at its next beat). Added `clearInterval(hbTimer);hbTimer=null;hbPeriod=0` in leaveGame. Test checks hbTimer null after leave (does not prove it was ever set).
5. HLAds.between: `Promise.race([ad, 15 s timer])` (hook HL_TEST_AD_MS), timer cleared when the ad ends. It resolves once, so a late ad cannot cause a second navigation. Test: hung ad (900 ms) with hook 250 ms returns in <700 ms, exactly 1 continuation.

## Not verified / risks
- Real Supabase (no network): real join latency. 3 s per try could be too short on a slow mobile link; a false failure just makes that phone leave and try the next advert or host. Owner can raise HL_TEST_QJOIN_MS default (each +1 s adds up to +2 s worst case).
- Merge edge: if a third phone joined the abandoning host in the same instant, that phone sees "host gone", leaves Play and returns home (pub rooms show no error). Guarded by the "no player peer" check but not impossible.
- Worst case 10.96 s is only about 1 s under the 12 s target on a loaded machine.
- Late ad can still show over the next screen after 15 s (cannot be cancelled); the HLNative wrapper should enforce its own timeout.
- Double tapping "Play again" while an ad is up can still call between() twice (pre-existing).
- mp_web.js prints no PASS line; I did not change that.
