# c09: tablet and desktop scaling
Files: NEW src/zz_c09.css (about 30 lines), NEW test/shot_tablet.py. No existing file edited, no JS touched (no hard-coded sizes needed fixing). No binary files.

## Mechanism
One variable. `--z` is set by stepped media queries on viewport HEIGHT (0.7 to 1.8 in 0.05 steps, aimed at about 860 CSS px of effective height, the phone design height). `html{zoom:var(--z)}` scales everything together: beans, type, buttons, slider, range bar, the fixed home scene (hills, trees, kite, sun), sheets, death stage. html/body/#app height becomes `100dvh / var(--z)` (needed because vh is not zoomed).
- Applies only when width >= 600 AND height >= 600, inside `@supports (zoom:1)`. Phones (including landscape phones, height < 600) match nothing: untouched.
- Also in that range: `#app{max-width:520px}` (was 760 below 820px wide, so iPad 768 stretched) and sheet cap 480.
- Portrait only: sun and hill heights reset to the phone values (the existing >=820px rule would have doubled them on top of the zoom and the sun covered the logo).
- Result: iPad 768x1024 z1.15, 820x1180 z1.35, 1024x1366 z1.6, Android 800x1280 z1.5, 1920x1080 z1.25, 1280x800 z0.95, landscape 1024x768 z0.9 (this one also fixed the "Who's ready" card being cut off on the secret screen).

## Not verified / risks
- Real iPad Safari / WKWebView: only Chromium tested. CSS `zoom` is supported in Safari/WebKit and Chrome, and Firefox 126+. If a WebKit version treats 100dvh inside zoom differently, the page would be too tall or short (guess; test on a real iPad or Xcode simulator before submitting).
- env(safe-area-inset-*) padding is also scaled by zoom (about 1.2x on iPad, small).
- Desktop 1280x800 is now 5% smaller (z0.95) on purpose. Wide desktop keeps the original left-side sun.
- Middle of duel and ask screens is empty vertical space, same as the phone layout (the layout is top and bottom anchored); proportionate, not redesigned.
- Landscape iPad works (z0.9 at 1024x768). a01 recommends portrait lock for phones; iPad landscape would need to be allowed if iPad is supported (Apple wants all iPad orientations unless the app opts out of multitasking).

## Recommendation
Support iPad now. The cost is low: this CSS makes every screen look intentional, and the store script (store/make_screens.py, ipad13 1032x1376) can produce the required 13" shots. Reasons: Apple reviews on iPad anyway, and a sparse or broken iPad layout is a common rejection and bad-review cause; ship iPhone-only only if there is no time to test on a real iPad first (the Safari zoom check above is the one unverified risk). If iPhone-only: do not claim iPad support, and the app still runs letterboxed on iPad. Note store/make_screens.py ipad13 size is 1032x1376 which now maps to z1.6.
Owner decision: iPad yes or no; allowed orientations on iPad.
